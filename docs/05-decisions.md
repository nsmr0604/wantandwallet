# 1. 確定した決定（ADR 形式・簡易）

| # | 日付 | 決定 | 理由 |
| --- | --- | --- | --- |
| D-01 | 2026-11-27 | 対象は**遊戯王 OCG（日本語）**。TCG は対象外 | ユーザーの実際の購買対象が OCG。価格・商品が日本の店舗前提 |
| D-02 | 2026-11-27 | 形態は**インストール型 PWA**（iOS/Android） | ストア審査・ビルド証明書なしで両 OS に届く。個人利用に十分 |
| D-03 | 2026-11-27 | **ローカル完結**（IndexedDB）。同期は将来 | まず「使える」ことが優先。同期は設計だけ確保 |
| D-04 | 2026-11-27 | 価格・在庫・購入は**型番（セットコード＋レアリティ）単位** | レアリティで価格が桁違いになるため、カード単位では比較にならない |
| D-05 | 2026-11-27 | スタックは **Svelte 5 + Vite + Dexie + Tailwind 4** | 小規模画面数・オフライン・バンドルサイズ重視。SSR 不要 |
| D-06 | 2026-11-27 | 配信は **Cloudflare Pages**（代替 GitHub Pages） | 無料・HTTPS・プレビュー・独自ドメイン可。ハッシュルーティングで SPA の 404 問題を回避 |
| D-07 | 2026-11-27 | カードデータは **`DawnbrandBots/yaml-yugi`（ja ロケール）** | `name.ja` / `text.ja` / OCG セット情報があり、公式 DB 由来で自動更新される。実データ取得で確認済み |
| D-08 | 2026-11-27 | カード画像は**扱わない**（テキストのみ） | 権利・容量・通信のコストに対して効果が小さい。後から C 要件で追加可 |
| D-09 | 2026-11-27 | 新弾発売日は**生成 JSON を同梱**し、アプリから外部サイトへ直接アクセスしない | CORS・規約・負荷の回避。取得失敗時も既存データを保持できる |
| D-10 | 2026-11-27 | 金額は**整数の円**。集計は Asia/Tokyo 固定 | 浮動小数の誤差とタイムゾーンずれを排除 |
| D-11 | 2026-11-27 | 通常削除は**論理削除（tombstone）**、物理削除は全削除のみ | 将来同期時の削除競合を解決できる形にしておく |
| D-12 | 2026-11-27 | YGOPRODeck は**将来の英語名・参考価格用**に降格 | 英語・TCG 中心で OCG 日本語要件を満たさない |
| D-13 | 2026-11-27 | 開発プロセスは**モックアップ型 × スパイラル型アジャイル**（[06-process.md](06-process.md)） | 最大リスクが「店頭での入力速度」と「カードデータ量」で、触って確かめる以外に判断できないため。仕様合意はモックで、技術リスクはスパイラルで潰す |
| D-14 | 2026-11-27 | **モック承認なしに実装しない**（レビューゲート）。承認は本ファイルに記録 | 手戻りコストを実装前に払う。個人開発でも「合意の記録」がないと判断がぶれる |
| D-15 | 2026-11-27 | モックアップは**捨てる前提**。実装コードの土台にしない | モックの作り込みが実装の負債になるのを防ぐ |
| D-16 | 2026-11-27 | L1 モックは **Svelte + Tailwind(CDN)** で作るが、**表示専用**（DB・domain・repository を持たない） | 見た目の再現度を上げつつ、モックのコードをそのまま実装に流用しない境界を引く。流用するのは「見た目と寸法の判断」だけ |
| D-17 | 2026-11-27 | S0 モック v0.1 を提出（`mockups/s0/`）。**承認待ち** | プロセスのゲート（実機幅・タップ領域・用語・未決事項）で判断するため |
| D-18 | 2026-11-27 | プロジェクト名は **wantandwallet**（欲しい＋財布。w の頭韻）。リポジトリは **public**・ライセンスなし | 用途（欲しいもの×予算）が名前で伝わり、覚えやすい。ディレクトリとドキュメントも同時に改名 |
| D-19 | 2026-11-27 | 公開リポジトリに**非公式である旨の免責**を明記 | 遊戯王は商標。公認・公式と誤認されないようにする |

# 3. 前提が崩れたときの影響

| 前提 | 崩れた場合の影響 | 代替 |
| --- | --- | --- |
| yaml-yugi が ja を提供し続ける | 日本語検索ができない | 公式カード DB のスクレイピング、または手入力＋CSV |
| 公式商品ページの構造が変わる | 新弾の自動取り込みが失敗 | 手動入力（R-63）で継続。取得部分は差し替え可能な 1 ファイルに隔離済み |
| iOS のストレージ退避が頻発する | データ消失 | JSON エクスポートの定期実施を促す。将来は同期で解消 |
| 1.3 万件の索引が大きすぎる | 初回ロードが遅い | 索引を「収録セットが新しいカード」に限定／検索をサーバーなしの分割ロードに |
