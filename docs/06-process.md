# 1. 全体像

外枠は**アジャイル**（短い反復・動くものを早く・振り返りで適応）。各反復の中身は**スパイラル**（リスクを先に潰す）で回し、各反復の入口に**モックアップ**（触れる仕様）を必ず置く。

```
┌─ スパイラル S(n) ──────────────────────────────┐
│                                                │
│  ① 目的とリスクを決める                        │
│        ↓                                       │
│  ② モックアップを作る（リスクを潰す試作）       │
│        ↓                                       │
│  ③ モックレビュー（実機幅で触る）               │
│     └ NG → ② へ戻る（実装しない）              │
│        ↓ GO                                    │
│  ④ 縦切りで実装（1 フローを端から端まで）      │
│        ↓                                       │
│  ⑤ 実機評価＋振り返り → S(n+1) の計画          │
│                                                │
└────────────────────────────────────────────────┘
```

**鉄則**: モック未承認の機能は実装しない。実装後の仕様変更は次のスパイラルへ送る（割り込みしない）。

# 2. なぜこの組み合わせか

| 手法 | 単独での弱点 | 組み合わせでの役割 |
| --- | --- | --- |
| アジャイルのみ | 「何を作るか」の合意が曖昧なまま走り、手戻りする | 反復のリズムと優先順位の見直しを担当 |
| モックアップ型のみ | 見た目は早いが、技術リスク（性能・オフライン・データ量）を潰さない | 仕様合意と UX 検証を担当 |
| スパイラル型のみ | 工程が重く、個人開発では回らない | リスクの大きい所から順に潰す判断を担当 |

wantandwallet の最大リスクは「店頭で本当に使えるか（入力速度・オフライン）」と「カードデータの量と日本語検索」。どちらも**触って確かめる以外に判断できない**ため、モック→実機→振り返りのループが効く。

# 3. スパイラルの中身

## ① 目的とリスク（30 分）

- このスパイラルで**利用者が新しくできること**を 1 文で書く
- リスクを 1 つ以上選ぶ（下のリスク登録簿から）。「今回はこれを潰す」を明言
- スコープ外を明記（やらないことを書く）

## ② モックアップ（リスクを潰す試作）

3 段階を使い分ける。

| 段階 | 形態 | 用途 | 置き場所 |
| --- | --- | --- | --- |
| L0 | 画面遷移図＋ワイヤー記述（Markdown / 手書き） | 情報の並び・導線の合意 | `docs/` に追記 |
| L1 | 単体 HTML（1 ファイル、Tailwind CDN、実データ風） | 実機幅での見た目・タップ領域・入力の重さ | `mockups/sN/` |
| L2 | 実装の一部を切り出した動く試作 | 性能・ライブラリ・API の技術検証 | `spikes/` |

**ルール**

- モックアップは**捨てる前提**。実装コードの土台にしない（コピペしない）
- L1 は必ず**実機（Xperia / iPhone）のブラウザ**で触る。PC の縮小表示で判断しない
- モックには**実データに近い文字列**を入れる（「カード名」ではなく「灰流うらら／QCCU-JP001／UR」）
- 数値は「桁が増えても崩れないか」を確認する（¥12,800 / 1,280 枚など）

## ③ モックレビュー（ゲート）

以下をすべて満たしたら GO。1 つでも NG なら ② に戻る。

- [ ] 主要フローが実機幅（360px）で 1 画面ずつ破綻しない
- [ ] 目標タップ数・入力数を満たす（§5 の指標）
- [ ] 用語が日本語として自然（「型番」「欲しいリスト」「巡回」）
- [ ] 未決事項（Q-xx）がこのスパイラル分だけ決まっている
- [ ] 承認を `docs/05-decisions.md` に記録した

## ④ 実装（縦切り）

- 1 スパイラル = **端から端まで動く 1 フロー**。横に広げない
- 例: 「店舗を 1 件登録 → 欲しいカード 1 枚 → 価格 1 件入力 → 比較表に出る」
- テストは domain の純関数から。UI はまず手動、固まったら E2E に固定
- 各スパイラル末にデプロイ（常に触れる URL がある状態を保つ）

## ⑤ 実機評価と振り返り（30 分）

- 実機で**自分の実際の買い物**に使ってみる（これが最良のテスト）
- 指標を測って記録（§5）
- 振り返り 3 行: 良かった / 詰まった / 次に変える
- 次スパイラルの目的とリスクを決める

# 4. スパイラル計画

| S | 目的（利用者ができること） | 潰すリスク | モック成果物 | 目安 |
| --- | --- | --- | --- | --- |
| S0 | ホーム画面から各機能へ移動でき、オフラインでも開く | PWA のインストール/更新/オフラインが iOS で成立するか | L0 全 9 画面の遷移図＋L1 ダッシュボード/タブ | 1 週 |
| S1 | 店舗と欲しいカードを登録できる | 型番モデルが実データで破綻しないか | L1 欲しいリスト・店舗管理・カード手入力 | 1 週 |
| S2 | 店舗を回って価格を記録し、最安を比べられる | **店頭で 1 枚 10 秒以内に入力できるか** | L1 巡回モード（テンキー）・比較表 | 1 週 |
| S3 | 購入を記録すると予算残が減る | 月境界・カテゴリ集計の正しさ | L1 購入登録・予算サマリ | 1 週 |
| S4 | 日本語名でカードを検索して型番を選べる | 1.3 万件の索引サイズと検索速度 | L1 検索・型番選択、L2 索引生成スパイク | 2 週 |
| S5 | 新弾の発売日と残り日数が見える | 公式ページ抽出の安定性・規約 | L1 新弾一覧、L2 抽出スパイク | 2 週 |
| S6 | バックアップと復元ができ、実運用に耐える | データ消失（iOS ストレージ退避） | L1 設定・エクスポート、実機 1 週間運用 | 1 週 |

# 5. 指標（各スパイラル末に実機で測る）

| 指標 | 目標 | 測り方 |
| --- | --- | --- |
| 価格入力 1 枚あたり | 10 秒以内 | 巡回モードで 10 枚入力しストップウォッチ |
| 価格入力のタップ数 | 3 タップ以内（数値入力含む） | 画面録画でカウント |
| 検索結果表示 | 300ms 以内 | 索引ロード後の入力→描画を DevTools |
| 初回ロード | 5MB 以下（gzip 前） | ビルド成果物の合計 |
| コールドスタート | 3 秒以内 | 実機で履歴から再起動 |
| オフライン起動 | 成功 | 機内モードで再起動 |

# 6. リスク登録簿

| ID | リスク | 影響 | 確率 | 対処 | 担当 S |
| --- | --- | --- | --- | --- | --- |
| K-01 | iOS でオフライン起動・更新が不安定 | 高 | 中 | 早期に S0 で実機確認。更新プロンプト実装 | S0 |
| K-02 | 店頭で入力が遅くて使わなくなる | 高 | 高 | テンキー UI をモックで検証。前回値プリセット | S2 |
| K-03 | 型番モデルが実データと合わない（set_code 空・再録） | 中 | 中 | 実カード 20 枚で L0/L1 検証。uniqueKey 規則を見直す | S1 |
| K-04 | カード索引が大きすぎて初回ロードが遅い | 中 | 中 | 索引縮小・分割・遅延ロード。S4 で計測 | S4 |
| K-05 | yaml-yugi のスキーマ変更で取り込みが壊れる | 中 | 低 | 必須フィールド検証＋失敗時は前回データ保持 | S4 |
| K-06 | 公式商品ページの構造変更 | 低 | 中 | 抽出を 1 ファイルに隔離。手動入力で継続可 | S5 |
| K-07 | iOS のストレージ退避でデータ消失 | 高 | 中 | エクスポート促し。1 週間運用テスト | S6 |
| K-08 | 集計の月境界・TZ ずれ | 中 | 低 | Asia/Tokyo 固定の純関数＋単体テスト | S3 |

# 7. 変更管理

- **モック段階**: 自由に変えてよい（コストが低い）
- **実装後**: 次スパイラルへ送る。緊急（バグ・データ破損）のみ割り込み可
- 仕様変更は `docs/05-decisions.md` に「なぜ変えたか」を 1 行で残す
- スコープを増やしたいときは、同じスパイラルの何かを C 要件へ落とす（総量を固定）

# 8. 成果物の置き場所

```
wantandwallet/
├── docs/            仕様・決定・ロードマップ（正）
├── mockups/         L1 モック（sN ごと。捨てる前提）
│   └── s0/
├── spikes/          技術検証（L2。残すか捨てるかは結果次第）
└── src/             実装
```

## モックの動かし方

```powershell
cd mockups/s0
npm install
npm run dev      # http://localhost:5180 / 実機は http://<PCのIP>:5180
```

- 実機のブラウザで開き、ホーム画面から同じ Wi-Fi 内で触る
- ヘッダー右の ☰ はモック専用の画面切り替え（実装には持ち込まない）
- レビュー結果と承認は `05-decisions.md` の「S0 モック レビュー記録」に書く
